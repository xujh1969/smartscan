# SmartScan 老照片批量拆分工具 — 设计规格

> 状态：**已批准**（2026-11-14）
> 来源：`grill-me` 会话逐分支追问，用户逐项确认（A/B/C/D/E 全部收敛），最终以「OK，请使用 superpowers 进行开发文档生成，然后进入正式开发」授权连续执行。
> 文档类型：superpowers brainstorming design spec
> 范围：v1，单机 Windows 桌面程序，不联网。

## 1. 目标

把「一次平铺扫描多张老照片」得到的大图，自动拆成一张张独立的、已扶正的水平照片，保存到用户指定的单一目录；提供缩略图预览页，用两个 ±90° 按钮（及批量旋转）纠正画面朝向。清晰度不得下降，DPI 等元数据不得丢失。

## 2. 非目标（明确不做）

云端上传、自动增强/去噪/锐化、任意角度手动微调、180° 自动判定、透视/单应性校正、凭空补全被遮挡像素、静默丢弃疑似照片、修改或移动原扫描件、命令行操作界面。

## 3. 已锁定的需求决策

### 3.1 输入 / 输出契约（分支 A）

| 项 | 决策 |
|---|---|
| 界面起点 | 多选任意目录的一批扫描图 + 指定一个输出根目录 + 「开始拆分处理」按钮 |
| 输出目录 | **只平铺 PNG**，不建任何子目录；`manifest`/日志/临时文件一律放 `%LOCALAPPDATA%\SmartScan\` |
| 文件格式 | 统一 PNG（无损）。输入可以是 JPEG/TIFF/BMP，其既有压缩损失被接受 |
| 命名 | `<批次内全局序号>_<8位内容哈希>.png`，如 `001_a3f2c1b9.png` |
| 元数据 | PNG `tEXt` 记录完整源路径、内容哈希、裁切框、扶正角、重叠标记、方向状态、置信度；`pHYs` 写原图 DPI；`iCCP` 写原 ICC；不强行塞 EXIF |
| 重跑 | 按「完整路径 + 内容哈希」匹配已有输出 → 跳过；未命中 → 追加新序号；**永不覆盖**；「覆盖重拆」需二次确认且会冲掉手动旋转成果 |
| 画质底线 | 不缩放、不自动增强、不二次压缩；倾斜扶正允许且仅允许一次 Lanczos 重采样；裁切用整数像素；90° 旋转为像素级无损重排 |
| 四角空白 | 用该扫描件估计的背景色填充；填充区域与角度写入元数据（界面可切 B 内接裁切 / C alpha，默认 A） |
| 旋转 | 预览只提供 ±90°；状态 0/90/180/270；「基准图 + 最终状态」就地落盘；点击后后台自动存盘，写盘成功才更新缩略图 |

### 3.2 检测与拆分（分支 B）

| 项 | 决策 |
|---|---|
| 真实形态 | 多数照片**无白边**、彼此**紧贴**、不保证间隙；接缝靠纸色/明暗阶跃（A）+ 细暗线/阴影（B）；混合少量有白边的照片 |
| 路线 | 两阶段：① 背景差分只切出「照片簇」；② 在**原始分辨率**上用直线段（LSD/Hough）、色阶、露背景小区域，加矩形/平行/直角先验拟合每张照片的四边形 |
| 边界 | 阴影有宽度会产生两条平行线，一律取靠照片**内侧**的边；无白边按纸色边界，最多向内收 0~1px |
| 几何模型 | 平面刚体旋转矩形（平移 + 旋转），不做透视校正 |
| 倾角 | ±20° 内自动扶正；超出标待复核，不硬猜 |
| 白边 | 自适应：检测到就保留；没有就按纸色边界裁 |
| 重叠 | 自动化优先：上层完整照直接输出；下层输出可见部分、缺口用背景色填充、标 `incomplete`；不阻断批次 |
| 遮挡推理 | 靠 T 型结点与边缘连续性判断谁在上；置信度低时退化为「两张都按可见部分输出 + 标 `uncertain`」，绝不把残缺照冒充完整照 |
| 质量倾向 | **宁可误报、不可漏掉**：低置信度/疑似误检照常输出并打标，结果页可筛选/删除/重拆，绝不静默丢照片 |
| 过滤 | 剔除贴边贯穿的扫描仪黑边、微小灰尘划痕；面积阈值按本批中位数自适应，保护小尺寸照片 |

### 3.3 方向判定（分支 C）

| 项 | 决策 |
|---|---|
| 语义 | 「竖拍/横拍」指**画面内容正着**（人站着、景物水平），不只是纸张幅面 |
| 自动判定 | 全离线，只用传统特征投票：人脸/人眼、地平线与长直线、文字行方向、天空/地面色调；**多个信号一致 + 高阈值**才自动转 90° |
| 判不准 | 保持扶正后原样，标 `orientation=unknown`，交预览页人工点 ±90° |
| 自动转过 | 记 `orientation=auto` + 证据/置信度，进「建议复核」筛选，可一键全部接受 |
| 手动转过 | 记 `orientation=manual` + 角度，覆盖 auto 标记，重跑不覆盖 |
| 180° | 不自动判定，由用户点两次 ±90° 解决 |
| 预览交互 | 每张缩略图上保留顺/逆时针两个按钮；额外允许多选 + 一键批量 ±90° + 键盘快捷键 |

### 3.4 交付与验收（分支 D / E）

Python 3.11+ / OpenCV / Pillow / NumPy / PySide6，PyInstaller 打成单文件绿色 Windows exe（免装 Python、离线、免管理员）；三页 GUI：选文件 → 可取消的进度页 → 结果预览页。后台逐文件处理、临时文件原子替换写盘、启动前检查目录可写与磁盘剩余空间。验收以 3~5 张典型样本试跑为准，召回优先，DPI/位深/色彩模式与源一致，600dpi 单张 CPU 10~20 秒，无 GPU 依赖。

## 4. 架构

```
run.py
  └─ smartscan/gui/app.py            MainWindow：三页切换、信号与后台线程
       ├─ pages/select_page.py       文件多选（可跨目录/拖拽）、输出目录、设置、开始
       ├─ pages/progress_page.py     进度、阶段、取消、日志
       └─ pages/result_page.py      缩略图网格、角标筛选、批量/单张 ±90°、双击看原图
  └─ smartscan/pipeline.py          批处理编排、取消、原子写盘、跳过判定、磁盘检查
       ├─ detection.py              背景估计 / 照片簇 / 接缝 / 四边形 / 遮挡推理
       ├─ split.py                  裁切 + 一次扶正 + 背景填充 + 缺口填充
       ├─ orientation.py            传统特征保守投票
       ├─ rotation.py              90° 无损旋转、基准图 + 最终状态
       ├─ metadata.py               PNG tEXt / pHYs / iCCP 读写
       ├─ naming.py                 序号 + 内容哈希、永不覆盖
       ├─ geometry.py               四边形、角度、内接矩形、点变换
       └─ models.py                 数据类与枚举（唯一共享语言）
```

依赖方向严格单向：`gui → pipeline → 各领域模块 → models`；领域模块**不依赖 PySide6**，因此可在无 GUI 环境下单测。`cv2/numpy/PIL` 只在 detection/split/orientation/metadata 中出现。

## 5. 核心数据流

1. `select_page` 收集 `list[Path]`（可跨目录、可能同名）+ 输出目录 + 设置 → `BatchConfig`。
2. `pipeline.run()` 启动前检查：输出目录可写、磁盘空间预估（按源文件大小 × 3 粗估 PNG 膨胀）、逐个源文件计算 `sha256[:8]`。
3. 对每个文件：Pillow 读取像素、DPI、ICC、色彩模式 → 背景估计（四角/边缘中位数）→ 前景掩码切出照片簇 → 簇内直线段 + 色阶 + 露背景小区域 → 拟合四边形 → 遮挡推理 → 每张生成 `PhotoQuad(status, confidence, occlusion_mask)`。
4. 每张：`geometry` 求倾角与内接矩形 → `split` 透视无关地做一次旋转（Lanczos）+ 裁切 + 背景色填充四角/缺口 → `orientation` 保守投票决定是否自动 ±90° → `naming` 取全局序号 → `metadata` 组装 → 临时文件写 PNG → `os.replace` 原子落盘 → 产出 `SplitResult`。
5. 汇总结果进 `result_page`；低置信度、`incomplete`、`uncertain`、`unknown`、`auto` 均以角标与筛选器呈现。
6. 用户旋转：`rotation` 以「首次拆分后的基准图」为源，按目标状态 0/90/180/270 一次性变换，更新 PNG `tEXt`，原子写盘成功后刷新缩略图。

## 6. 模块接口（唯一职责）

| 模块 | 关键接口 | 职责 / 依赖 |
|---|---|---|
| `models.py` | `PhotoQuad`, `SplitResult`, `BatchConfig`, `OrientationState`, `Flags` | 纯数据类，零依赖 |
| `geometry.py` | `order_quad`, `tilt_angle`, `largest_inscribed_rect`, `rotate_points`, `quad_bbox` | numpy；不做图像 I/O |
| `naming.py` | `content_hash(path)`, `next_name(index, digest)`, `find_existing(meta_list, path, digest)`, `reserve_name(dir, name)` | 哈希、序号、永不覆盖 |
| `metadata.py` | `build_text_chunk(...)`, `read_metadata(path)`, `write_png(path, image, dpi, icc, text)` | Pillow；DPI/ICC/文本块 |
| `rotation.py` | `apply_state(image, state)`, `rotate_90(image, clockwise)`, `state_after(state, step)` | numpy/PIL；像素级无损 |
| `orientation.py` | `vote(image)`, `should_auto_rotate(votes)` | cv2；返回 `unknown` 或非 0 角度 |
| `detection.py` | `estimate_background`, `find_photo_cluster`, `detect_quads`, `resolve_occlusion` | cv2/numpy；返回 `list[PhotoQuad]` |
| `split.py` | `deskew_and_crop(image, quad, background)`, `fill_gaps(...)` | cv2/PIL；唯一允许重采样的地方 |
| `pipeline.py` | `run(config, progress, cancel)`, `estimate_disk_need`, `atomic_save` | 编排、错误隔离、取消、原子写盘 |
| `gui/*` | `MainWindow`, 三个 page 类 | PySide6；仅通过 `pipeline`/`rotation`/`metadata` 交互 |

## 7. 错误处理

| 情况 | 行为 |
|---|---|
| 某张扫描图打不开 / 解密失败 | 记日志，标失败，继续下一张，不中断批次 |
| 检测不到任何四边形 | 整张进「待复核」清单（GUI 展示），不输出到结果目录 |
| 四边形置信度低 | 照常输出并打标 `low_confidence`（宁可误报） |
| 遮挡关系判不准 | 两张三按可见部分输出 + `uncertain` |
| 写盘失败 / 磁盘满 | 删除临时文件，标失败，继续；不留下半截 PNG |
| 用户取消 | 当前文件完成后停止，已落盘结果保留，状态持久化在 PNG 元数据 |
| 输出目录不可写 / 空间不足 | 启动前报错，不开始处理 |
| 程序崩溃后重启 | 读取结果目录 PNG 的 `tEXt` 恢复旋转状态与来源映射 |
| 同名源文件跨目录 | 内容哈希 + 全局序号保证不覆盖、不误判已完成 |

## 8. 测试策略

- `pytest`，纯逻辑单测覆盖 `geometry` / `naming` / `metadata` / `rotation` / `orientation` / `models`。
- 图像类测试用 numpy 合成扫描图：白/灰背景、带倾角矩形、彼此紧贴、压角重叠、阴影线、小尺寸照片；断言检测数量、倾角误差、无内容裁切、DPI 保持、原子写盘。
- GUI 用 `QT_QPA_PLATFORM=offscreen` 构造 `MainWindow`，验证三页存在、按钮可用、批量旋转信号连通，不做像素级截图比对。
- 每个生产函数先有失败测试（TDD 红→绿），测试只断言行为不断言内部实现。
- 验收：3~5 张真实典型扫描件试跑，人工核对召回优先、边缘未被切、四角填充自然、朝向正确。

## 9. 验收清单（可逐条勾选）

- [ ] 结果目录只有 PNG，无子目录，文件名含全局序号与 8 位内容哈希
- [ ] 输出 DPI、位深、色彩模式与源一致；`tEXt` 可回读来源与旋转状态
- [ ] 紧贴无白边、有白边、倾斜、重叠、小照片五类样本均被拆出，无静默丢失
- [ ] 倾斜照片输出为水平，四角用背景色填充，照片内容未被内接裁切
- [ ] 重叠：上层完整、下层 `incomplete`；低置信度遮挡标 `uncertain`
- [ ] 判不准方向的照片保持原样标 `unknown`；自动转过的可被筛选复核
- [ ] ±90° 单张/批量旋转后磁盘文件与缩略图一致，重启后状态可恢复
- [ ] 重跑跳过已完成文件、永不覆盖；取消后已完成结果保留
- [ ] 全程 GUI，无命令行交互；单文件 exe 可离线启动

## 10. v1 实现边界与已知限制（实现完成后补入）

本节用于消除规格描述与实际代码之间的偏差；若与前文措辞冲突，以本节为准。开发方自测结果见 `progress.md`。

- **输入位深**：仅自动处理 8bit/通道的 L / RGB / RGBA 扫描件。16bit 或特殊模式**不降位深输出**，整张记为失败并在日志中提示人工处理。
- **白边**：与扫描背景同色的白边会被背景差分并入背景，不单独保留；照片本体不受影响。真实形态以"多数无白边"为主。
- **结果页**：提供角标筛选、每张两个 ±90° 按钮、多选批量旋转与快捷键、双击缩略图查看放大图与元数据（**不叠加检测框**）。v1 不提供手动补框、单张删除、单张重拆。
- **待复核 / 失败文件**：计入 `BatchResult.review` / `failed`，在进度页汇总并写入 `%LOCALAPPDATA%\SmartScan\logs\smartscan.log`；结果页只展示成功拆出的 PNG。
- **日志**：落在应用数据目录，不出现在结果目录；结果目录始终只有 PNG。
- **三种四角策略**：背景色填充（默认）、内接裁切、透明角均已实现，可在选择页切换。
- **打包**：PyInstaller 单文件命令见 README；本轮**未执行打包**，`dist/SmartScan.exe` 未生成，不虚构产物。
- **真实样本**：自动方向判定为保守传统特征投票；自动率与检测准确率必须用 3~5 张真实扫描件人工复核。合成图测试只证明链路正确，不能替代真实样本验收。
- **性能**：600dpi 单张 10~20 秒为设计目标，未在真实大幅面样本上做基准测试。

### 真实样本验收结论（2026-11-14）

样本：用户提供的一批 9 张 2550×3508、300dpi、RGB 扫描 PNG。结果：耗时约 13s，输出 35 张 PNG，失败 0，5 个源文件因超倾角进待复核（照片仍已输出并打 `low_confidence`）。本地验收产物为 `verify_index.png`、`verify_output_report.json`、`verify_output/`，均不纳入版本库。

- **已修复的根因**：原实现用全局亮度 k-means 把照片内部色块当成不同照片，第一张样本输出 23 个碎片；改为「连续长直线段接缝检测（Hough 投影）+ 实心主体裁剪 + 超倾角不静默丢弃」后，第一张正确输出 3 张完整照片，57 项自动化测试全绿。
- **仍存在的问题（未继续调参，等待人工决策）**：
  1. 少量空白/纯色块误检与极小碎片（最小 21×10）；符合已批准的「宁可误报不可漏掉」，但 v1 结果页缺少删除功能，需在资源管理器手工删除。
  2. 个别 2×2 拼贴扫描件未被完全切开，多张照片合并为一张输出（召回不足）。
  3. 个别近正方形照片 `tilt=90`，输出为横躺，需要预览页 ±90° 纠正。
  4. `incomplete` 9 张、`uncertain` 1 张、`low_confidence` 8 张为保守标记，不阻断输出。
