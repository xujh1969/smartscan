# 2026-11-14 照片边界检测排查与验证

## 已确认原因

1. 旧检测把连续长直线投影成贯穿整个照片簇的行列网格。水面、建筑、栏杆会误触发；错位排列中，一张照片的边界还会切进旁边的照片。
2. 在前景掩膜上闭运算会连接原本独立的窄间隙。背景取四角像素的整体中位数，容易被占据角落的照片污染。
3. 裁切复用前景掩膜，照片中接近扫描背景的高光会被擦除。
4. 按最长边计算倾角，会把直立竖幅照片当作需要旋转 90°。
5. 重跑只检查来源与哈希，会跳过旧算法生成的错误结果。

## 当前修正

- 新增有限长度纸边分区：浅色窄脊线需要两侧较暗的证据，按实际长度切开区域，再拟合各自的轮廓。水天亮度阶跃和建筑暗线不构成这种证据。
- 紧凑、完整的矩形不因内部直线直接切开。缺少纸边的几何切分降低置信度，加入来源待复核清单。
- 去掉连接窄间隙的闭运算；裁切保留完整轮廓内部像素；减少扫描杂线拖长边界的情况。
- 扶正角限制到小角度，保留横竖幅；PNG 记录检测版本，同版可跳过，旧版会重新处理且不覆盖原文件。

## 验证口径

原始 57 项测试通过；新增合成场景与本机样本回归。第 6 张实拍扫描件要求得到 5 张，并对人工核对的完整照片范围检查交并比超过 0.85；第 39、43 张分别要求保留为一张。私有照片不提交仓库。

本机对全部 43 张扫描件生成了检测框预览。`verify_output/baseline.jpg` 是修改前，`verify_output/after.jpg` 是修改后；预览框和数量只是诊断材料，不是准确率。完整批处理的文件、运行错误、待复核来源和逐图输出数见 `verify_output_report.json`。

本次完整批处理：43 个来源、278 个候选 PNG、0 个运行失败、34 个来源待复核，耗时约 156 秒。已逐个检查 PNG 可解码、300 DPI 和检测版本元数据。最终声明依赖范围内的 OpenCV 4.14.0 环境下，68 项测试和 GUI 启动自检通过，43 个来源的检测数量与导出报告一致。

## 仍未解决的验收项

- 第 1、3、5、7、8、9 张等没有明显纸边的紧贴照片，以及部分 2×2 排列，仍可能被合并。
- 第 16 张等浅色照片容易将天空或白色纸边排除在定位范围外，数量正确也不能视为完整裁切。
- 仍需逐张边界标注，分别测量完整照片召回、误切、合并和四边偏移，不能用写出多少个文件代替成功率。
- 只做了本机界面启动自检，新增结果仍需要用户的视觉验收。

## 替代路线试验

在仅位于本机忽略目录的试验中，对比了局部纸边、分层阈值、直线局部分区，以及 MobileSAM 点提示和现有开源扫描拆分检测器。通用分割可能识别照片中的人和物，或把整组照片当成一个对象；这些试验没有解决全部紧贴照片，因此没有作为生产依赖引入，也没有复制第三方检测代码。

目前建议采用“自动候选 + 可保存的人工框校正”工作流处理含糊边界。若要求完全自动，应建立带边界标注的训练/验收集，并评估专门的照片实例检测模型；不能把通用分割模型的名称当作效果保证。
